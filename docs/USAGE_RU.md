явный словарь фигур и описания ходов словами, без оценок и фильтрации.

GIF всех партий доступны прямо в [README](../README.md).

## Шахматная партия

### Основной режим: Jev самостоятельно

По уточнению пользователя основной режим теперь **`raw` по умолчанию**.
Программа передаёт FEN, доску с координатами, полную историю в UCI и SAN и **все**
легальные ходы в фиксированном порядке. Jev сама выбирает ход. Код не оценивает
кандидатов, не отсеивает зевки, не запрещает повторения и не заменяет ответ модели.
Общие требования беречь фигуры и избегать бесполезных повторений находятся только
в текстовой инструкции. Никаких оценок Stockfish, рассчитанных угроз или лучших
ходов в запросе нет. Формат SAN — обычная шахматная запись, включая шах и мат.

```bash
.venv/bin/python chess_demo.py --max-turns 60

# Посмотреть полный запрос без API
.venv/bin/python chess_demo.py --dry-run

# Jev самостоятельно, Stockfish играет только за соперника
.venv/bin/python chess_demo.py --policy raw --opponent stockfish --skill 5
```

По умолчанию чёрными играет прежний простой локальный бот. Его поиск вызывается
только для его собственного хода; оценки не передаются Jev. Правила легальности
и завершения партии проверяет `python-chess`. Доступные заявления ничьей
принимаются автоматически для обеих сторон; это правило стенда, не решение Jev.
Новая партия: `results/chess-pure-v4/replay.html`. Версия инструкции сохранена
в PGN/JSON: `pure-v2-history`. Отличия от первой партии — усиленная общая инструкция
и дополнительная SAN-история; веса модели не менялись.

### Архив исследования: варианты с помощниками

**Следующие режимы не используются по умолчанию и не оценивают самостоятельную
игру Jev.** Они сохранены, чтобы результаты исследования можно было воспроизвести.

```bash
.venv/bin/python chess_demo.py --policy engine --opponent stockfish --skill 5 --max-turns 80

# Сильнее соперник (шкала Stockfish 0–20, это не Elo)
.venv/bin/python chess_demo.py --policy engine --opponent stockfish --skill 10 --max-turns 80
```

Локально установлен Stockfish 14.1 из пакета Ubuntu (`.tools/stockfish/extracted/usr/games/stockfish`).
Он не заменяет системные программы. На другой машине можно установить Stockfish
системным менеджером пакетов и указать `--engine-path /path/to/stockfish`;
также автоматически проверяется PATH.

`--policy engine` — **Jev с подсказками Stockfish**, не чистая Jev. Движок
анализирует до 5 кандидатов с лимитом `--coach-nodes 100000`, Jev выбирает среди
ходов в пределах 40 сантипешек от лучшего. Обнаруженный кратчайший мат имеет
приоритет. Для соперника задан `--opponent-nodes 15000` и отдельный Skill Level.
Оба процесса используют по одному CPU-потоку, 64 MiB hash. Такие бюджеты —
настройка демонстрации, не одинаковые условия силы сторон или рейтинг человека.
Stockfish Skill включает случайное ослабление; `--seed` относится только к
старому простому боту и не делает Stockfish-партии детерминированными.

История всех UCI-ходов передавалась Jev и раньше. Теперь дополнительно по истории
проверяется, повторит ли кандидат позицию и сможет ли соперник заявить ничью.
При оценке лучшего хода ≥1.5 пешки повторения исключаются, если среди близких
к лучшему есть вариант без повторений. В проигранных позициях возможность
спастись ничьей сохраняется. Если хорошей альтернативы нет, повторение разрешено.
Полный запрет циклов не гарантируется: анализ ограничен бюджетом и пятью кандидатами.

Сильная демонстрация: `results/chess-coach-v3-skill5/replay.html`.
В `game.json` и PGN сохранены версия движка, параметры, кандидаты и выбранные ходы.
Если отфильтрован только один вариант, запрос Jev всё равно выполняется; число
таких ходов нужно учитывать при оценке реальной роли модели.

### Исходные режимы

Jev играет белыми против простого локального бота: перебор на два полухода,
оценка материала/мата, случайный выбор при равенстве с фиксированным seed.
Это слабый учебный соперник, не Stockfish. Jev получает FEN, текстовую доску
с координатами, историю и все легальные ходы в UCI с SAN-описаниями.
Движок правил `python-chess` проверяет легальность. Исторический `--policy guarded`:
локальный фильтр проверяет каждый ход, все немедленные ответы соперника и цепочки
легальных взятий на одной клетке (до 6 полуходов после первого взятия).
При наличии альтернатив отсекает обнаруженные потери материала и мат в один ход;
матующие ходы имеют приоритет. Если безопасных ходов не найдено, оставляет варианты
с минимальной оценённой потерей. Jev получает оставшиеся ходы и оценки разменов,
плюс усиленную инструкцию. Это модель с программной тактической помощью.
Дальние комбинации, промежуточные ходы, шахи внутри цепочки размена и позиционная
компенсация не просчитываются полностью. Фильтр может отвергнуть хорошую жертву
или пропустить угрозу: это ограниченная эвристика, не гарантия безопасности.
`--policy raw` использует интерфейс без фильтра и подсказок (основной режим).
Первоначальные точные запросы сохранены в `results/chess-first-game/game.json`;
текущая общая инструкция расширена, поэтому запросы не идентичны первой версии.
Один API-запрос на ход белых, чёрные не используют API. Игра ждёт ответа.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-chess.txt
.venv/bin/python chess_demo.py --max-turns 60

# Исходный режим без тактической помощи
.venv/bin/python chess_demo.py --policy raw --max-turns 60

# Офлайн-разбор партий тем же тактическим фильтром
.venv/bin/python analyze_chess.py results/chess-first-game/game.json results/chess-guarded-v2/game.json

# Посмотреть запрос без вызова API
.venv/bin/python chess_demo.py --dry-run

# Все тесты, включая шахматные
.venv/bin/python -m unittest discover -s tests -v
```

В `results/chess-.../` сохраняются `replay.html` (интерактивная доска с ползунком
и воспроизведением), `game.pgn` и `game.json` (полные запросы, ответы, токены,
стоимость по API). Отчёт обновляется после каждого хода; во время партии для
обновления страницы нужен reload. Первая партия: `results/chess-first-game/replay.html`.
Просмотр записанной партии работает без сети и не делает API-запросов.
Повторная партия с фильтром: `results/chess-guarded-v2/replay.html`.
Число найденных тем же фильтром ошибок — проверка его работы, не независимая
оценка шахматной силы. Соперник и seed сохранены, но позиции после изменения
ходов различаются. Вариант с одной только новой инструкцией отдельно не измерялся.

Максимум по умолчанию — 60 запросов / 120 полуходов. Лимит означает остановку
незавершённой партии (`*`), а не ничью. При возможности заявить ничью по повторению
или правилу 50 ходов программа автоматически её принимает. Ошибка API останавливает
игру и сохраняет прогресс. Вероятности выбора хода не равны вероятностям победы.
Одна партия не определяет силу или рейтинг Jev; вызовы API не обучают её веса.

## Задачи Decisions API

Python 3.10+, без установки библиотек. Модель отвечает на типизированные вопросы о тексте, объекте или массиве: `noul` — вероятность «да», `choice` — выбор категории, `score` — оценка по упорядоченной рубрике. Свободный текст она не генерирует.

По умолчанию используется `typesafe/jev-1.13` и `https://openrouter.ai/api/alpha/decisions`. Формат запроса взят из Quick Start OpenRouter, предоставленного пользователем. Страницы моделей: [Jev 1.13](https://openrouter.ai/typesafe/jev-1.13), [Latest](https://openrouter.ai/~typesafe/jev-latest). Это alpha API: несовместимые ответы сохраняются для диагностики и останавливают прогон.

## Запуск

Создай `.env` по образцу `.env.example` и впиши ключ (либо задай переменную окружения `OPENROUTER_API_KEY`, она имеет приоритет). `.env` и результаты исключены из Git.

```bash
# Один запрос: проверка подключения
python3 jev.py --scenario routing-refund

# Все 24 примера: 24 последовательных запроса
python3 jev.py

# Только проверка утверждений / ранжирование
python3 jev.py --scenario verification
python3 jev.py --scenario ranking

# Проверка стабильности: 3 повтора четырёх правил = 12 запросов
python3 jev.py --scenario rules --repeat 3

# Алиас последней версии
python3 jev.py --model '~typesafe/jev-latest' --limit 2

# Свой текст, вопросы и необязательные ожидаемые ответы
python3 jev.py --input examples/custom.json

# Оценка статьи по редакционной политике: контекст передаётся объектом
python3 jev.py --input examples/content.json
```

Каждый прогон создаёт отдельную папку `results/run-.../`: `report.html` открывается в браузере, `results.json` содержит исходные примеры, ответы API, метки, ошибки и длительность. Отчёт обновляется после каждого запроса. При первой ошибке прогон останавливается; автоматических повторов нет. `--out results/my-run` задаёт папку явно и перезаписывает отчёт в ней. `--timeout 45` — тайм-аут сетевых операций в секундах. `Ctrl+C` останавливает прогон.

## Что проверяем

| Группа | Примеров | Практическое применение и проверка |
|---|---:|---|
| `routing` | 7 | Команда поддержки, срочность, недовольство. Отрицания, английский, неопределённость, попытка навязать ответ. |
| `verification` | 6 | Подтверждается ли утверждение данным источником: верные факты, числа, выдумки, частичная правда, перефразирование. |
| `ranking` | 4 | Релевантность документов запросу о сбросе пароля. Сравни `relevance.score`: ожидаем direct > partial > related > irrelevant. |
| `rules` | 4 | Политика возврата: граница 14 дней, просрочка, использованный товар, отсутствие данных. Для реальных точных правил предпочтительнее обычный код; здесь проверяем следование условиям. |
| `meaning` | 3 | Совпадение намерений: перефразирование, отрицание, русский ↔ английский. |

Вопросы и примеры можно менять в `scenarios.py`. `--list` выводит все ID. `--limit N` ограничивает число примеров до применения `--repeat`. `expected` никогда не передаётся модели.

## Как оценивать

- **Accuracy**: совпадение с ручной меткой, для `noul` порог 0.5. Шкалы `score` субъективны и не включены в accuracy. Ошибки запросов считаются отдельно и исключаются из знаменателя.
- **Brier**: средний квадрат ошибки вероятности для бинарных вопросов; 0 лучше всего. Уверенная ошибка штрафуется сильнее. На таком маленьком придуманном наборе нельзя доказать калибровку или общее превосходство модели.
- **Вероятности**: смотри распределения, особенно на близких категориях. Для реальной автоматизации порог принятия решения надо подобрать на своих размеченных данных; сомнительные случаи можно направлять человеку.
- **Score**: сохраняется ровно как вернул API, вместе с распределением; это не процент уверенности. Для ранжирования сравнивай оценки только при одинаковой рубрике.
- **Время**: длительность полного запроса с этой машины, включая сеть. Медиана считается по успешным запросам; в demo время не характеризует API.
- **Стоимость**: суммируем только `usage.cost`, если API его вернул. `requests_with_cost` показывает полноту данных; `null` не означает бесплатно. Цену вручную не умножаем на неизвестный объём токенов.

Для сравнения запусков сохрани модель, одинаковые примеры и рубрики. Повторы не являются новыми независимыми тестовыми примерами. Следующий полезный шаг — добавить 50–100 собственных примеров с заранее заданными метками и проверить ошибки по группам.

## Без ключа

```bash
python3 jev.py --dry-run --limit 1
python3 jev.py --demo
python3 -m unittest discover -s tests -v
```

`--dry-run` выводит тела запросов без сети. `--demo` создаёт отчёт с явно отмеченными синтетическими ответами: все вероятности равномерные; это проверка отображения, а не результат модели.
